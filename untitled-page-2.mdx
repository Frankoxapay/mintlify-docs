<Steps>
  <Step title="Create a sandbox invoice" id="create-a-sandbox-invoice">
    Create a hosted invoice with `POST /v1/payment/invoice`. Set `sandbox` to `true` so you can test the payment flow without using real cryptocurrency.

    Use a small request first. You only need the amount plus your Merchant API Key; `currency`, `order_id`, and `callback_url` make the example easier to connect to a real application.

    <CodeGroup>

    ```bash cURL
    curl --request POST \
      --url https://api.oxapay.com/v1/payment/invoice \
      --header "merchant_api_key: $OXAPAY_MERCHANT_API_KEY" \
      --header "Content-Type: application/json" \
      --data '{
        "amount": 49,
        "currency": "USD",
        "order_id": "order_1245",
        "callback_url": "https://example.com/webhooks/oxapay",
        "sandbox": true
      }'
    ```

    ```javascript Node.js
    const response = await fetch("https://api.oxapay.com/v1/payment/invoice", {
      method: "POST",
      headers: {
        merchant_api_key: process.env.OXAPAY_MERCHANT_API_KEY,
        "Content-Type": "application/json",
      },
      body: JSON.stringify({
        amount: 49,
        currency: "USD",
        order_id: "order_1245",
        callback_url: "https://example.com/webhooks/oxapay",
        sandbox: true,
      }),
    });
    
    const result = await response.json();
    console.log(result);
    ```

    ```python Python
    import os
    import requests
    
    response = requests.post(
        "https://api.oxapay.com/v1/payment/invoice",
        headers={
            "merchant_api_key": os.environ["OXAPAY_MERCHANT_API_KEY"],
            "Content-Type": "application/json",
        },
        json={
            "amount": 49,
            "currency": "USD",
            "order_id": "order_1245",
            "callback_url": "https://example.com/webhooks/oxapay",
            "sandbox": True,
        },
    )
    
    print(response.json())
    ```

    ```php PHP
    <?php
    
    $payload = json_encode([
        "amount" => 49,
        "currency" => "USD",
        "order_id" => "order_1245",
        "callback_url" => "https://example.com/webhooks/oxapay",
        "sandbox" => true,
    ]);
    
    $ch = curl_init("https://api.oxapay.com/v1/payment/invoice");
    
    curl_setopt_array($ch, [
        CURLOPT_POST => true,
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => [
            "merchant_api_key: " . getenv("OXAPAY_MERCHANT_API_KEY"),
            "Content-Type: application/json",
        ],
        CURLOPT_POSTFIELDS => $payload,
    ]);
    
    $response = curl_exec($ch);
    curl_close($ch);
    
    echo $response;
    ?>
    ```

    </CodeGroup>

    ```json Relevant response fields
    {
      "data": {
        "track_id": "PAYMENT_TRACK_ID",
        "payment_url": "https://pay.oxapay.com/...",
        "expired_at": 1734546589,
        "date": 1734510589
      }
    }
    ```

      Store `track_id` on your own order or payment record. You’ll use it to reconcile webhook events and retrieve payment information later.

  <Step title="Handle and verify payment webhooks" id="handle-and-verify-payment-webhooks">
    OxaPay sends payment updates to the `callback_url` in your invoice request. Payment callbacks can include an in-progress `Paying` state followed by a confirmed `Paid` state.

    Verify every callback before trusting it. OxaPay signs the **raw request body** with HMAC-SHA512 using your Merchant API Key and sends the signature in the `HMAC` header.

    <CodeGroup>

    ```javascript Node.js
    import crypto from "node:crypto";
    
    const signature = req.headers["hmac"] ?? "";
    const rawBody = req.rawBody; // capture before JSON parsing
    
    const expected = crypto
      .createHmac("sha512", process.env.OXAPAY_MERCHANT_API_KEY)
      .update(rawBody)
      .digest("hex");
    
    const receivedBuffer = Buffer.from(signature);
    const expectedBuffer = Buffer.from(expected);
    
    const valid =
      receivedBuffer.length === expectedBuffer.length &&
      crypto.timingSafeEqual(receivedBuffer, expectedBuffer);
    
    if (!valid) {
      return res.status(401).send("invalid signature");
    }
    
    const event = JSON.parse(rawBody.toString());
    
    if (event.status?.toLowerCase() === "paid") {
      // Mark the order paid exactly once.
    }
    
    return res.status(200).send("ok");
    ```

    ```python Python
    import hashlib
    import hmac
    import json
    import os
    
    raw_body = request.get_data()  # capture before JSON parsing
    signature = request.headers.get("HMAC", "")
    
    expected = hmac.new(
        os.environ["OXAPAY_MERCHANT_API_KEY"].encode(),
        raw_body,
        hashlib.sha512,
    ).hexdigest()
    
    if not hmac.compare_digest(expected, signature):
        return "invalid signature", 401
    
    event = json.loads(raw_body)
    
    if event.get("status", "").lower() == "paid":
        # Mark the order paid exactly once.
        pass
    
    return "ok", 200
    ```

    </CodeGroup>

    <Warning>
      Do not fulfill an order when the payment is only `Paying`. Wait until the payment reaches the confirmed paid state and the webhook signature has been verified.
    </Warning>

    Your callback endpoint should return HTTP `200` with the response body `ok` after successful processing. If delivery fails, OxaPay retries webhook delivery, so make your handler idempotent.

    <Accordion title="Payment states you'll commonly handle">
      | Status | What it means | Recommended action |
      | --- | --- | --- |
      | `new` / `waiting` | The payment has not completed yet. | Keep the order pending. |
      | `paying` | A payment has been detected or is being processed. | Wait for confirmation. |
      | `paid` | The invoice has been fully paid. | Fulfill once after verification. |
      | `underpaid` | The invoice did not receive the full required amount. | Apply your underpayment policy. |
      | `expired` | The payment window ended before completion. | Do not fulfill. |
    </Accordion>

    [Read the complete webhook guide →](/webhooks)
  </Step>
  <Step title="Reconcile the payment by track ID" id="reconcile-the-payment">
    Webhooks should drive normal payment updates, but your backend should also be able to retrieve the current payment state using the `track_id` you stored earlier.

    Call `GET /v1/payment/{track_id}` with the same Merchant API Key.

    <CodeGroup>

    ```bash cURL
    curl --request GET \
      --url "https://api.oxapay.com/v1/payment/PAYMENT_TRACK_ID" \
      --header "merchant_api_key: $OXAPAY_MERCHANT_API_KEY" \
      --header "Content-Type: application/json"
    ```

    ```javascript Node.js
    const trackId = "PAYMENT_TRACK_ID";
    
    const response = await fetch(
      `https://api.oxapay.com/v1/payment/${trackId}`,
      {
        headers: {
          merchant_api_key: process.env.OXAPAY_MERCHANT_API_KEY,
          "Content-Type": "application/json",
        },
      }
    );
    
    const result = await response.json();
    console.log(result);
    ```

    ```python Python
    import os
    import requests
    
    track_id = "PAYMENT_TRACK_ID"
    
    response = requests.get(
        f"https://api.oxapay.com/v1/payment/{track_id}",
        headers={
            "merchant_api_key": os.environ["OXAPAY_MERCHANT_API_KEY"],
            "Content-Type": "application/json",
        },
    )
    
    print(response.json())
    ```

    ```php PHP
    <?php
    
    $trackId = "PAYMENT_TRACK_ID";
    $ch = curl_init("https://api.oxapay.com/v1/payment/" . $trackId);
    
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => [
            "merchant_api_key: " . getenv("OXAPAY_MERCHANT_API_KEY"),
            "Content-Type: application/json",
        ],
    ]);
    
    $response = curl_exec($ch);
    curl_close($ch);
    
    echo $response;
    ?>
    ```

    </CodeGroup>

    Use this lookup for reconciliation, support tooling, or cases where a webhook is delayed.
